What is broken

Ordered by what costs you the most. Each finding was verified against the live HTML or a headless render, not inferred.

Critical

The Article schema script throws on every post

The detail_blog template's footer code builds an Article object, then reads the modified date from #dateUpdated. That element does not exist — the template renders it as id="updatedOn". querySelector returns null, .innerHTML throws, and the script aborts before injecting anything.

var dateModified = document.querySelector('#dateUpdated').innerHTML;
                                           ^^^^^^^^^^^^ renders as #updatedOn

Confirmed two ways: id="dateUpdated" appears in 0 of 264 crawled post pages, and a headless render of a live post throws Cannot read properties of null (reading 'innerHTML') with no Article node in the resulting DOM.

Cost: no article rich results, no author attribution, no freshness signal on the entire blog.
Critical

The fallback credits the company, not the writer — and drops both dates

A second, site-wide script injects a BlogPosting only when no Article schema exists. Because of the bug above, that condition is always true, so this is what actually ships on every post:

"author": { "@type": "Organization", "name": "inBeat Agency" }
// no datePublished, no dateModified

Google gets a corporate author and zero publication dates, on a blog where the visible byline and both dates are sitting right there in the HTML. Even if the Article script were repaired, it would emit "March 19, 2026" rather than ISO 8601, which is not a valid date value.

Cost: the E-E-A-T signal you built an Authors collection for never reaches search or AI crawlers.

Author pages carry only the site-wide Organization graph — the same block that appears on all 421 pages. There is no Person node, no sameAs, no photo, no job title, on any URL. The Authors collection cannot supply them either: it has exactly three fields — Bio, Name, Slug.

Cost: no author entity for Google or an LLM to attach expertise to.

High

All structured data is injected by JavaScript

Static HTML contains only the Organization + ProfessionalService graph. Breadcrumbs, Article and BlogPosting are all appended to <head> after DOMContentLoaded. Google renders JavaScript, so this mostly works for Google — but GPTBot, ClaudeBot, PerplexityBot and CCBot largely do not. Your robots.txt deliberately invites all of them; they arrive and find no article markup.

Cost: the AI-crawler access you opened up is spent on pages with no machine-readable article data.
High

The dedicated Title Tag field is ignored by the template

The Blogs collection has a title-tag field. The template does not use it — it binds the full article name instead, with a stray double space:

{{name}}  - inBeat Agency        ← double space, and name is often 80+ chars

Only 2 of the 100 sampled blog items have title-tag filled. Result across the site: 257 of 421 titles exceed 60 characters, 129 exceed 80, and the longest is 118 — "Short-Form vs Long-Form Video Content: EXPERT Tips to Choose the Best Format for Your…"

Cost: Google rewrites or truncates the majority of your title tags.
Medium

Category pages use the URL slug as their meta description

The detail_categories template binds description to the slug field, so the ten category pages ship descriptions reading ugc, advertising, ppc-and-google-ads. Titles carry no brand suffix. The Categories collection has only Name and Slug, so there is nothing better to bind to. They also sit at /blog-author/categories/…, nested under the author folder.
